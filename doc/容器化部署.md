# 容器化部署

### Docker安装

1. **Docker** 适合单个容器操作（镜像、容器、卷、网络）
2. **Docker Compose** 适合 **多服务项目编排**，可以一条命令启动/停止多个服务。

```shell
# 更新包索引
sudo apt-get update

# 安装依赖
sudo apt-get install -y \
    ca-certificates \
    curl \
    gnupg \
    lsb-release
    
# 添加 Docker 官方 GPG key
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# 添加 Docker 软件源
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
  
# 安装 Docker
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 验证版本
docker --version

# Docker
docker run hello-world

# Docker Compose（新版）
docker compose version

# Docker Compose（旧版二进制）
docker-compose version
```

```shell
# 将当前用户加入 docker 用户组
sudo usermod -aG docker $USER
# 重新登录或运行以下命令生效
newgrp docker
# 测试
docker ps
```

### Docker常用命令

#### 镜像Image

```dockerfile
docker images                  			# 查看本地镜像
docker search <name>           			# 搜索镜像
docker pull <name>:<tag>       			# 拉取镜像（默认 latest）
docker rmi <image_id>          			# 删除镜像
docker build -t <name>:<tag> . 			# 根据 Dockerfile 构建镜像
docker tag <image_id> repo/name:tag   	# 给镜像打标签
```

#### 容器Container

```dockerfile
docker ps                      # 查看正在运行的容器
docker ps -a                   # 查看所有容器（包括已停止）
docker run -it <image> bash    # 启动容器并进入交互式终端
docker run -d --name myapp <image>   # 后台运行并命名容器
docker exec -it <container> bash     # 进入已运行容器
docker start <container>       # 启动已停止的容器
docker stop <container>        # 停止容器
docker restart <container>     # 重启容器
docker rm <container>          # 删除容器（需先停止）
docker logs -f <container>     # 查看实时日志
docker cp <container>:/path ./ # 从容器拷贝文件出来
```

#### 网络Network

```dockerfile
docker network ls              					# 查看网络
docker network inspect <name>  					# 查看网络详情
docker network create <name>   					# 创建网络
docker network connect <network> <container>  	# 将容器接入网络
docker network disconnect <network> <container> # 移除容器的网络连接
docker network rm <name>       					# 删除网络
```

#### 卷Volume

```dockerfile
docker volume ls               # 查看卷
docker volume inspect <name>   # 查看卷详情
docker volume create <name>    # 创建卷
docker volume rm <name>        # 删除卷
docker volume prune            # 删除未使用的卷
```

#### 系统清理

```dockerfile
docker system df               # 查看镜像、容器、卷占用空间
docker system prune            # 清理无用数据（容器、网络、镜像）
docker system prune -a         # 更彻底，连未使用的镜像也删除
```

#### 实际使用

```dockerfile
# 快速启动一个基础的nginx容器
# 拉取nginx镜像（可选）
docker pull nginx:latest
# 运行容器 docker run
# 使用 -p 参数将本地的端口映射到容器内端口（Nginx默认监听80端口） 将宿主机20001端口映射到容器80端口
# 使用 -d 参数指定为后台运行程序
docker run --name my-nginx -p 25000:80 -d nginx
# 停止运行中的容器
docker stop my-nginx
# 重启停止后的容器 并重新指定端口映射
docker ps -a
docker rm -f my-nginx
docker run --name my-nginx -p 25000:80 -d nginx
docker ps
curl http://localhost:25000
# 进入容器内部进行调试
docker exec -i -t my-nginx bash
```



### DockerCompose常用命令

#### 启动容器

| 命令                         | 说明                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| docker-compose up            | 启动 `docker-compose.yml` 中定义的所有服务，并在前台显示日志。<br>如果镜像不存在，会先构建镜像。 |
| docker-compose up -d         | `-d` 表示后台运行（detached mode）                           |
| docker-compose up --build    | 强制重新构建镜像，即使镜像已经存在。                         |
| docker-compose up -d --build | 后台运行并强制重建镜像                                       |

#### 停止与删除容器

| 命令                          | 说明                                           |
| ----------------------------- | ---------------------------------------------- |
| docker-compose stop           | 停止所有服务，但不删除容器。                   |
| docker-compose down           | 停止并删除容器、网络、默认卷（但不删除镜像）   |
| docker-compose down --rmi all | 停止并删除容器、网络、默认卷、镜像（彻底清理） |
| docker-compose down -v        | 同时删除卷数据                                 |

#### 查看状态与日志

| 命令                               | 说明                           |
| ---------------------------------- | ------------------------------ |
| docker-compose ps                  | 查看服务的运行状态             |
| docker-compose logs                | 查看所有服务日志               |
| docker-compose logs -f             | 实时跟踪日志（类似 `tail -f`） |
| docker-compose logs <service_name> | 查看指定服务日志               |

#### 构建镜像

| 命令                            | 说明                               |
| ------------------------------- | ---------------------------------- |
| docker-compose build            | 根据 `docker-compose.yml` 构建镜像 |
| docker-compose build --no-cache | 不使用缓存，完全重新构建镜像。     |

#### 重启容器

| 命令                                  | 说明               |
| ------------------------------------- | ------------------ |
| docker-compose restart                | 停止并重新启动服务 |
| docker-compose restart <service_name> | 只重启指定服务     |

#### 执行命令进入容器

| 命令                                    | 说明                                    |
| --------------------------------------- | --------------------------------------- |
| docker-compose exec <service_name> bash | 进入容器交互式终端（前提是容器有 bash） |
| docker-compose exec <service_name> sh   | 容器没有 bash 时，用 sh                 |

#### 其他操作

| 命令                                        | 说明                                       |
| ------------------------------------------- | ------------------------------------------ |
| docker-compose pull                         | 拉取服务所需镜像（用于更新镜像）           |
| docker-compose run <service_name> <command> | 新建一个临时容器执行命令，不影响原有容器。 |
| docker-compose config                       | 查看解析后的 `docker-compose.yml` 配置。   |
| docker-compose version                      | 查看 Docker Compose 版本                   |
| docker-compose ps -a                        | 查看所有容器（包括停止的）                 |

1. 如果修改了 `Dockerfile` 或镜像配置，最好用 `docker-compose up -d --build` 启动
2. 日志调试时可以先用 `docker-compose up` 不加 `-d`，方便看到实时输出。
3. 清理无用镜像、卷、网络可以用 `docker system prune`，保持环境整洁。

#### 命令对比

| 功能                      | Docker 命令                                                  | Docker Compose 命令                               |
| ------------------------- | ------------------------------------------------------------ | ------------------------------------------------- |
| **启动容器**              | `docker run -d --name myapp -p 8080:80 nginx`                | `docker-compose up -d`                            |
| **构建镜像并启动**        | `docker build -t myapp . && docker run myapp`                | `docker-compose up -d --build`                    |
| **停止容器**              | `docker stop <container>`                                    | `docker-compose stop`                             |
| **重启容器**              | `docker restart <container>`                                 | `docker-compose restart`                          |
| **删除容器**              | `docker rm <container>`                                      | `docker-compose down`                             |
| **删除容器+卷+网络**      | `docker rm -f $(docker ps -aq)` + `docker volume prune` + `docker network prune` | `docker-compose down -v`                          |
| **删除容器+卷+网络+镜像** | `docker system prune -a`                                     | `docker-compose down -v --rmi all`                |
| **查看容器状态**          | `docker ps -a`                                               | `docker-compose ps`                               |
| **查看日志**              | `docker logs -f <container>`                                 | `docker-compose logs -f`                          |
| **进入容器**              | `docker exec -it <container> bash`                           | `docker-compose exec <service> bash`              |
| **运行一次性命令**        | `docker run --rm <image> <cmd>`                              | `docker-compose run --rm <service> <cmd>`         |
| **构建镜像**              | `docker build -t myapp .`                                    | `docker-compose build`                            |
| **拉取镜像**              | `docker pull <image>`                                        | `docker-compose pull`                             |
| **检查网络**              | `docker network ls`                                          | （Compose 默认自动创建 `<project>_default` 网络） |
| **检查配置**              | （无直接命令）                                               | `docker-compose config`                           |



### 相关问题

#### 为什么要保证每个服务都是独立的容器？

1. 服务管理便捷\运维简单：
   - 进程和容器对应，容器的退出码直接就是服务的退出码（方便监控、健康检查）
   - 容器编排工具（docker-compose / k8s）能直接探测某个服务存活情况并自动拉起。
   - 如果将所有服务塞进单个容器，需要自己写脚本拉起一堆进程，这违背了容器的初衷，运维和监控将变得复杂。
2. 进程生命周期解耦：
   - 在裸机中所有服务跑在同台机器上，某个服务挂掉可能拖垮整个进程组。
   - 独立容器后，`msg_server` 崩溃不会影响 `login_server`、`db_proxy_server`，可以单独重启而不是重启整个大容器。
3. 依赖管理清晰：
   - 各个服务的依赖环境不同，独立容器可以有自己裁剪过的运行环境，不必在一个大容器里装一堆没必要的依赖，镜像更小更干净。
4. 配置与日志隔离：
   - 每个容器挂载自己的 `conf`、`log` 目录，排查问题时不会一堆日志混在一起。
   - CI/CD 更新的时候，可以只替换某个服务的镜像，而不用全量更新。
5. 迁移到Kubernetes更自然：
   - 在k8s中Pod对应服务，独立容器部署未来直接搬到k8s中就是开箱即用。

#### 基础服务容器为什么推荐直接使用官方镜像？

MySQL、Redis、Nginx这种基础服务通常推荐直接用官方镜像，而不是自己重新编译：

1. 稳定性与安全性：
   - 官方镜像由 MySQL/Redis/Nginx 的维护团队或 Docker 官方维护，包含安全补丁和已验证的构建流程。
   - 如果自己编译，可能会因为依赖版本、编译参数不同导致运行行为和预期不一致，还容易漏掉安全更新。
2. 节省时间和维护成本：
   - 官方镜像已经打包好运行环境，`docker run mysql:5.7` 就能启动。
   - 如果自己构建，要写 Dockerfile+下载源码 + 编译 + 配置，复杂度高很多。
   - 后期维护时只需要 `docker pull redis:6.2` 就能升级，而不是重复整个编译过程。
3. 可配置性强：
   - 官方镜像支持通过环境变量或挂载配置文件进行定制：
   - MySQL：`MYSQL_ROOT_PASSWORD`、`MYSQL_DATABASE`
   - Redis：挂载 redis.conf
   - Nginx：挂载 conf.d

#### 什么时候考虑自建镜像？

确实有特殊需求，官方镜像满足不了下，可以选择自建镜像。

1. 需要用特定编译选项（比如 Redis 要裁剪某些模块、Nginx 要加额外模块）
2. 对安全性有极端要求（不信任官方镜像来源，要全链路自建）
3. 公司内部有统一的镜像规范（比如必须基于某个公司维护的基础镜像）
4. 否则优先使用官方镜像，必要时再在其基础上二次定制（`FROM mysql:5.7` + 加一些配置脚本）

#### 容器\网络\默认卷\镜像之间的关系？

| 概念             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| 镜像 (Image)     | 容器的模板，包含操作系统、应用程序及依赖。只读，可多次创建容器。 |
| 容器 (Container) | 镜像的运行实例，是一个独立的进程环境。容器可以挂载卷和连接网络。 |
| 网络 (Network)   | 容器间通信的虚拟网络。Docker Compose 会为项目默认创建一个网络。 |
| 卷 (Volume)      | 用于持久化存储数据，即使容器删除，卷里的数据仍然存在。Docker Compose 默认会创建项目卷，也可以自定义。 |

启动流程Docker compose：

1. 检查镜像是否存在：如果 `docker-compose.yml` 指定的镜像不存在 → 先 `build` 或 `pull` 镜像。
2. 创建网络：Compose 会为当前项目创建一个默认网络，所有服务默认连接此网络（网络名一般是 `项目名_default`）。
3. 创建卷：Compose 会根据 `volumes` 配置创建卷，如果没有指定，默认卷会自动生成。
4. 启动容器：镜像创建 → 挂载卷 → 连接网络 → 启动服务。

对应操作命令：

| 命令                          | 说明                                   |
| ----------------------------- | -------------------------------------- |
| docker-compose up             | 创建网络 → 创建卷 → 启动容器（用镜像） |
| docker-compose up --build     | 先 build 镜像 → 再创建网络、卷、容器   |
| docker-compose down           | 删除容器 + 网络（卷默认保留）          |
| docker-compose down -v        | 删除容器 + 网络 + 卷                   |
| docker-compose down --rmi all | 删除容器 + 网络 + 卷 + 镜像            |
